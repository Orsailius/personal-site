Fundamentals of Unity
  • - Game is composed of scenes. Scenes are a tree of GameObjects. Multiple scenes can be loaded at once
  • - GameObjects are objects that exist in the world. They are always tied to a Transform. Transforms have position, rotation and scale.
  • - Unity doesn't primarily use Object-Oriented Programming, it uses something similar to an Entity Component System
  • - Classes that extend MonoBehaviour are attached to GameObjects to give them functionality. Example, Collider lets it collide, Renderer lets it appear, Health to give it hp etc.
  • - MonoBehaviours have builtin methods that 'override' base methods
  • Awake - runs as soon as created before start
  • Start - runs right before the first update - put init code here
  • Update - runs every frame
  • - Monobehaviours run independently and in 'random' order, if a crash would happen in other programs it will prolly just break the single behaviour. This prevents game crashes (very good) but introduces random ass bugs
  • - Public variables of 'serializable' types are exposed in the inspector, ie they can be set in the editor. This is 'the' primary concern when scoping
  • - Besides from GameObjects the other major type of objects are ScriptableObjects. These hold data. Store data in code or in scriptable objects instead of a database
